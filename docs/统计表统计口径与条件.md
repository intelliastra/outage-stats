# 统计表统计口径与条件

本文说明“统计表.xlsx”如何从停电用户数据、历史结果和业务配置生成。统计表模板的两张正式 Sheet 为“2026年统计表”和“2025年统计表”；每行是地市或公司合计。以下是当前代码口径，阈值是否与甲方最终签认条件一致仍应以业务确认的规则表为准。

## 一 输入、时间和版本

日常统计读取最新停电用户表。在 Excel 后端，上传文件中的最早至最晚停电开始日构成闭区间，用本次文件整段替换该窗口内的历史记录；窗口外仍取上次处理结果。窗口内没有数据的日期不从历史回填，因此纠错重导可能令停电数减少。PostgreSQL 后端读取当前已激活的有效版本。报告把前次成功结果、当前来源及统计规则版本保留在比较说明中，同日期范围再次生成时使用新的文件名，不覆盖旧版。

日常统计继续读取按年度上传的“表11重大事件日统计表”。它是日期剔除配置，不是外力破坏原因码文件。国家能源局线路台账仅用于统计表中“纳入国家能源局管控线路”那一组。

2026年统计表用本次有效数据截止日及当年数据。2025年统计表从2025年基准停电用户数据取得去年同期范围，按同样的清洗、分类与互斥统计方法重算。历史旧报告不因重算而覆盖。

## 二 从原始行到计数对象

在进入频繁停电判定前，代码依次标记重大事件日、停电时长小于5分钟、单一用户工单，以及同一用户和馈线在6小时窗口内需合并的重复停电。原始行及“不统计原因”仍保留在处理结果中；用于指标计算的只是不被剔除的行。六小时合并的具体业务边界应以已确认算例为准，不能因为统计表去重就改变停电事实本身。

原脚本分析时按“用户编码＋所属馈线编码”形成停电用户明细，再形成用户清单和线路清单。本次仅调整**统计表中的人数和线路数**：同一用户编码在同一组只计一户，同一馈线编码只计一条线路；多命中的标签仍留在明细，汇总只归最高优先级类别。若同一对象出现多个地市，程序按来源中出现次数最多的地市归属，平局按地市名称稳定排序，并记录冲突警告；业务方仍需核实真实归属。

## 三 分类条件与优先级

### 频繁停电，高于所有预警

1. 一年内停电次数**超过5次**。
2. 连续60天内停电次数**超过3次**。
3. 一年内预安排停电次数**超过3次**。

若同一户或线路同时命中多个频繁条件，按上面顺序只计入第一类。三个标签仍可在原明细中出现；统计表子列和合计均按互斥归属计算。

### 频繁对象之外的预警

1. 近30天停电**2次**。
2. 近50天停电**3次**。
3. 一年内停电**4～5次**。

同一对象命中多个预警时，按“30天2次 > 50天3次 > 年4～5次”选一类。已计入频繁组的户或线路，不再进入预警组。当前脚本的30天和50天条件采用等于指定次数；本次优化不擅自改变“等于／超过”的阈值。

## 四 模板各列怎么填

| Sheet与列 | 对象和类别 | 合计列 |
| --- | --- | --- |
| 2026年 B–E | 预警用户：年4～5、50天3、30天2 | E＝B＋C＋D |
| 2026年 F–I | 预警线路：年4～5、50天3、30天2 | I＝F＋G＋H |
| 2026年 J–M | 频繁用户：年>5、60天>3、预安排>3 | M＝J＋K＋L |
| 2026年 N–Q | 频繁线路：年>5、60天>3、预安排>3 | Q＝N＋O＋P |
| 2026年 R–U | 以上频繁线路中“是否纳入国家能源局台账＝是” | U＝R＋S＋T |
| 2025年 B–E | 去年同期频繁用户三类 | E＝B＋C＋D |
| 2025年 F–I | 去年同期频繁线路三类 | I＝F＋G＋H |
| 2025年 J–M | 去年同期频繁线路中纳入国家能源局台账三类 | M＝J＋K＋L |

每个地市合计应等于该组子列之和，公司合计由各地市同列计数相加。不同组是不同业务集合，不把“用户数”和“线路数”相加。频繁与预警跨组互斥，但仍应单独展示各自合计。

## 五 与上次成功日报比较

处理结果中的“本次较上次变化说明”列，解释当前用户的新增、次数增减或分类变化；已从本次结果消失的户或线路在“变化明细”Sheet中保留上次分类、停电次数及工单／用户／馈线／时间定位。页面与两份停电摘要单独列出减少数量及净变化。对比同时读取**上次统计表实际显示的 B～U 列数值**，因此能区分“旧口径合计较高、本次互斥统计后合计下降”与“某户实际退出频繁清单”；不能仅用去重后的旧清单人数冒充旧报表显示值。

可查的记录变化不必然证明是源数据错误，也可能来自统计口径、日期推进或剔除配置变更；证据不足时需回查来源与批准规则，不能自动归责。首次运行或找不到同年份完整的上次报告时，显示“暂无可比基准”，不把减少误写成0。

## 六 外力破坏模块与日常统计的关系

两页各自上传**内容相同的未经人工筛除的停电用户表**，外力任务启动前核对文件 SHA-256。外力模块在全部 Sheet 读取后、任何统计前确认 AE 列为“责任原因代码”，排除以 `513`、`514`、`515` 开头的所有原始用户行，包括四位码 `5132`、`5142`、`5150`。日常统计不应用此过滤。空代码和其他前缀保留；缺 AE 列报错，不输出未过滤的外力结果。外力输出追加“外力过滤说明”Sheet，记录原始、各类剔除、剩余、空代码行数及原文件哈希。

表11重大事件日期剔除仍是独立规则；日常统计和外力统计各自使用已批准的日期配置。新增原因码过滤不能替代其他十一类业务剔除规则。

## 七 验收时怎样对账

用同一输入、同一数据截止日和同一规则版本准备标准样例，检查同户多馈线、同线路多用户、多标签、恰好阈值、跨年、重复上传、历史重导、缺日期和表11变更。逐地市核对明细去重后的分类人数／线路数、子列和合计，再核对公司合计。对变化明细逐条回查工单和停电时间；对外力过滤核对 `513*`、`514*`、`515*` 与保留的其他代码。正式阈值或归属发生变更时，应发布新规则版本并保存旧报告，不能直接覆盖旧结果。
